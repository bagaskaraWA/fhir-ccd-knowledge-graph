\section{Recommendation Queries}
\label{app:queries}
The query below is the one evaluated per patient to produce the applicable
recommendation set; Listing~\ref{lst:applicable-core} in Chapter~III shows its
core. It is reproduced verbatim from the evaluation module.

\begin{lstlisting}[caption={Applicable recommendations for one patient.},label={lst:applicable-full}]
MATCH (p:Patient {uid:$pid})
WHERE EXISTS { (p)<-[:SUBJECT]-(:Condition)-[:CODE]->(:Code)<-[:SAME_CONCEPT]-(:Concept {umlsCui:$gate}) }
MATCH (rec:Recommendation)
WHERE NOT rec.cor STARTS WITH '3'
OPTIONAL MATCH (rec)-[:TARGETS]->(tc:Concept)
  WHERE tc.umlsCui <> $gate
    AND ( EXISTS { (tc)-[:SAME_CONCEPT]->(:Code)<-[:CODE]-(:Condition) }
       OR EXISTS { (tc)-[:SAME_CONCEPT]->(:Code)<-[:CODE]-(:Procedure) } )
WITH p, rec, collect(DISTINCT tc) AS extraConds
WITH p, rec, extraConds,
     [tc IN extraConds WHERE
        EXISTS { (p)<-[:SUBJECT]-(:Condition)-[:CODE]->(:Code)<-[:SAME_CONCEPT]-(tc) }
        OR EXISTS { (p)<-[:SUBJECT]-(:Procedure)-[:CODE]->(:Code)<-[:SAME_CONCEPT]-(tc) }] AS matched
WHERE size(extraConds) = 0
   OR (coalesce(rec.targetLogic, 'AND') = 'OR'  AND size(matched) >= 1)
   OR (coalesce(rec.targetLogic, 'AND') = 'AND' AND size(matched) = size(extraConds))
RETURN rec.recommendationId AS recId
\end{lstlisting}

\section{Modules and Their Outputs}
\label{app:modules}
Table~\ref{tab:modules} names the twelve modules of the pipeline proper. Several further
scripts support them without forming part of it: \texttt{cohort.cypher} defines the CCD
cohort by clinical criterion; \texttt{make\_worksheets.py} generates the manual-labelling
packet and \texttt{build\_gold\_labels.py} consolidates the filled worksheets into
\texttt{eval/gold\_labels.csv}.

The evaluation rests on two reference standards, and the filenames distinguish them:

\begin{itemize}
  \item \texttt{silver\_oracle.py} encodes the guideline logic and labels every
  patient by reading the raw FHIR bundles, writing \texttt{eval/silver\_oracle\_labels.csv}.
  Its output is generated, not curated.
  \item \texttt{eval/gold\_labels.csv} holds the manual labels, produced by a human
  reading the guideline text against the patient record.
  \item \texttt{crs\_eval.py} scores the system against either standard;
  \texttt{obs\_gate.py} evaluates the observation gate;
  \texttt{pick\_review\_patients.py} ranks the cohort for the manual sample.
  \item \texttt{subjektif\_audit.py} measures the subjective data in the 30 sample patients'
  FHIR records---clinical notes, chief complaints, cardiac symptoms, functional scales,
  patient-reported questionnaires and angina diagnoses---and writes
  \texttt{eval/subjektif\_audit.txt}, which supports the limitation on cardiac symptom data in
  Section~\ref{sec:limitations}.
  \item \texttt{kappa\_bootstrap.py} estimates confidence intervals for the silver--gold
  $\kappa$ with a bootstrap that resamples patients as well as cells, and reports the
  prevalence index, bias index, PABAK and a per-patient jackknife; its output
  \texttt{eval/kappa\_bootstrap.txt} supports Section~\ref{sec:kappa-ci}.
  \item \texttt{predicate\_audit.py} audits where the reference standard shares a predicate
  with the system under test, proves the two are the same function over 200{,}876 feature
  vectors, and reports the concordance once the shared-predicate recommendations are removed;
  its output \texttt{eval/predicate\_audit.txt} supports Section~\ref{sec:shared-predicate}.
  \item \texttt{csv\_gate.py} rebuilds the observation gate from Synthea's CSV export alone,
  compares it against the FHIR bundle path, and writes
  \texttt{eval/csv\_gating\_experiment.txt}. It is the script that produces the figures in
  Section~\ref{sec:csv-gating}.
  \item The \texttt{telaah-klinisi/} directory holds the clinician-review toolchain.
  \texttt{buat\_telaah.py} and \texttt{perbarui\_lembar.py} build the review sheet and its key
  file. \texttt{baca\_hasil.py} reads the completed sheets into one table, and
  \texttt{analisis\_hasil.py} computes the rating proportions, the per-patient bootstrap
  intervals, and the inter-rater agreement reported in Section~\ref{sec:clinician}.
\end{itemize}

\subsection{Idempotent Load}
Listing~\ref{lst:loader-merge} gives the four write statements the loader issues. Every one
is a \texttt{MERGE}, which is what allows a bundle to be reloaded without duplicating a
node, a code or an edge---the property the \texttt{:Patient} count in
Section~\ref{sec:kg-results} confirms. The backticked names are interpolated per resource
type and per field.

\begin{lstlisting}[caption={The loader's write path (\texttt{loader.py}).},label={lst:loader-merge}]
// nodes -- one statement per FHIR resource type
UNWIND $rows AS row
MERGE (n:Resource {uid: row.uid})
SET n += row.props SET n:`<ResourceType>`

// shared terminology nodes, keyed on (system, code)
UNWIND $rows AS row
MERGE (c:Code {system: row.system, code: row.code})
ON CREATE SET c.display = row.display

// resource-to-resource references
UNWIND $rows AS row
MATCH (s:Resource {uid: row.src})
MATCH (t:Resource {uid: row.dst})
MERGE (s)-[:`<FIELD>`]->(t)
RETURN count(*) AS n      // a shortfall means a MATCH found no node

// resource-to-code edges
UNWIND $rows AS row
MATCH (s:Resource {uid: row.src})
MATCH (c:Code {system: row.system, code: row.code})
MERGE (s)-[:`<FIELD>`]->(c)
\end{lstlisting}

\subsection{The Observation-Gate Predicate}
Each entry of \texttt{OBS\_GATE} is a predicate over graph-derived features.
\texttt{decide} lets it \emph{override} the graph's gate-and-\texttt{AND} decision rather
than intersect with it, so a disjunctive branch such as \texttt{RAAI:1} adds patients
instead of filtering them out.

\begin{lstlisting}[language=Python,caption={The observation gate (\texttt{obs\_gate.py}), abridged.},label={lst:obs-gate}]
OBS_GATE = {
    "CCD-2023:BB:1":    lambda f: f["lvef_min"] is not None and f["lvef_min"] <= 40,
    "CCD-2023:BB:2":    lambda f: f["lvef_min"] is not None and f["lvef_min"] < 50,
    "CCD-2023:SGLT2:4": lambda f: f["hf"] and f["lvef_min"] is not None
                                  and f["lvef_min"] <= 40,
    "CCD-2023:RAAI:1":  lambda f: f["htn"] or f["dm"] or f["ckd"]
                                  or (f["lvef_min"] is not None and f["lvef_min"] <= 40),
    "CCD-2023:WM:2":    lambda f: f["bmi_ge25"],
    # ... ten further predicates, one per observation-gated recommendation
}
OBS_GATED = set(OBS_GATE)

def decide(graph_applicable, feats):
    keep = {r for r in graph_applicable if r not in OBS_GATED}
    if feats.get("ccd"):          # obs-gated recs fire only for CCD patients
        keep |= {r for r, pred in OBS_GATE.items() if pred(feats)}
    return keep
\end{lstlisting}

\subsection{The Briefing Prompt}
The prompt is what bounds the language model to the retrieved facts; the faithfulness
check of Section~\ref{sec:faithfulness} then verifies that the bound held.

\begin{lstlisting}[caption={The grounded-briefing prompt (\texttt{crs\_briefing.py}), abridged.},label={lst:briefing-prompt}]
SYSTEM
You are summarizing decision-support facts retrieved from a clinical knowledge
graph for a physician treating a patient with chronic coronary disease (CCD).
The briefing INFORMS the clinician; it does not make the decision.

USER
Write a clinician-facing briefing from the JSON facts below, in TWO clearly-headed
parts: a MAIN BRIEFING a cardiologist reads in 30 seconds, then a DETAILS chapter
for drill-down.

CONTENT RULES (strict -- these preserve trust):
- Use ONLY the facts provided. Never add recommendations, drugs, doses, or
  evidence that are not present in the JSON.
- Justify applicability ONLY from `requiresAlso` and the patient's actual
  `conditions` / `medications`. A rec's OTHER text preconditions are NOT
  established facts about this patient. If a rec's action assumes such an
  unconfirmed precondition, phrase the action CONDITIONALLY, never as an
  assertion.
- Every item in `applicable` and `safetyFlags` MUST appear at least once, named
  by its recommendation id. You may GROUP and COMPRESS them, but never drop one.
- Never alter a COR value, and never attach a PMID to the wrong recommendation.
- State a count only if it equals the number of items given.
- If a list is empty, say so explicitly -- do not fill the gap.

[... the two part templates follow, then the JSON facts payload ...]
\end{lstlisting}
